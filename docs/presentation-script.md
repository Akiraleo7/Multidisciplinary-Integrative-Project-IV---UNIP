# HEJ Care Suite - Presentation Script

## Suggested duration

Use a 10-15 minute demonstration. Keep the explanation focused on the
implemented MVP and identify planned extensions honestly.

## 1. Context and objective

Explain that HEJ Care Suite addresses fragmented hospital workflows by
centralizing patient intake, emergency triage, and hospitalization operations.
The presentation release demonstrates a functional vertical slice rather than
claiming that every hospital department is already implemented.

## 2. Architecture

Show the dependency direction:

```text
API -> Infrastructure -> Application -> Domain
```

Mention that the API serves the responsive web interface, Application contains
use cases, Infrastructure persists data in SQL Server, and Domain contains
business rules.

## 3. Deployment smoke test

1. Open the deployed application.
2. Call `GET /health`.
3. Show the HTTP 200 response:

```json
{"status":"ok","service":"HEJCareSuite.Api"}
```

Mention that GitHub Actions validates restore, Release build, tests, frontend
syntax, and Docker image creation.

## 4. Functional demonstration

1. Log in with the local demonstration account.
2. Register a patient and show the patient list.
3. Edit the patient and demonstrate validation.
4. Delete the patient only if a disposable demonstration record is being used.
5. Select a patient and register an emergency triage record.
6. Show the triage history and risk classification.
7. Admit a patient to a bed.
8. Show the admission history.
9. Discharge the patient with mandatory notes.
10. Log out and show that protected operations require authentication.

## 5. Database evidence

Run `database/006_validation_queries.sql` in SSMS and show:

- schema versions `1` through `5`;
- core tables and constraints;
- filtered indexes for active beds and patients;
- audit triggers;
- audit records generated by the demonstration.

## 6. Testing and limitations

State that Domain, Application, and API tests run in CI and that the container
build is validated automatically. State clearly that exams, pharmacy,
role-specific dashboards, native mobile delivery, and complete physician
confirmation are planned extensions, not completed MVP features.

## 7. Closing message

Close by emphasizing the delivered value: a working, tested, auditable,
containerized hospital MVP with a reproducible deployment path and a clear
backlog for the next cycle.
