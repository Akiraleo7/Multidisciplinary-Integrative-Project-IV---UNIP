## 2026-10-10 - Unit testing baseline

- Added xUnit projects for the Domain and Application layers.
- Added tests for patient validation, normalization, identity creation, and registration.
- Kept Application tests independent of SQL Server by using an in-memory test double.
- Tests follow Arrange-Act-Assert structure and can run with `dotnet test`.
- Added API integration tests using `WebApplicationFactory` and an isolated repository
  test double for the HTTP patient contract.
- Fixed the API test project imports and test-double visibility so the full solution
  compiles in the Codespace.
- Isolated each API integration test in its own `WebApplicationFactory` instance to
  prevent shared fixture state from affecting assertions.
- Updated the API GET test to compare stable patient fields after JSON deserialization;
  entity identity is generated by the domain constructor and is not a transport contract.
- Added a `PatientResponse` DTO to keep the HTTP contract independent from the Domain
  entity model.
- Added the first web vertical slice for patient intake and listing under
  `src/HEJCareSuite.Api/wwwroot`.
- Added idempotent operational indexes for patient name lookup and audit-log queries
  in `database/002_operational_indexes.sql`.
- Added an API request DTO and centralized ProblemDetails handling for patient
  validation errors.
- Updated the web slice to display API ProblemDetails messages instead of replacing
  them with a generic client-side error.
- Added patient update support across Domain, Application, SQL persistence, API, and
  the web interface, including an integration test for `PUT /api/v1/patients/{id}`.
- Completed the patient CRUD slice with audited deletion through
  `DELETE /api/v1/patients/{id}` and a confirmation action in the web interface.
- Added the authentication baseline: PBKDF2 password verification, SQL user storage,
  login endpoint, demo schema seed, and a login form in the web slice.
- Added cookie-based authentication and authorization for patient endpoints. Integration
  tests now use an explicit test authentication scheme, while the web UI loads patients
  after successful login.
- Fixed API test authentication compilation by importing `ILoggerFactory` and renaming
  the test scheme constant to avoid hiding the framework's inherited `Scheme` member.
- Added explicit logout through the cookie authentication endpoint and the web UI.
- Added the first emergency triage vertical slice: Domain risk classification,
  Application use case, SQL schema/repository, authenticated API endpoints, and
  indexed patient history lookup.
- Resolved a C# namespace collision between the `Application.Triage` namespace and
  the Domain `Triage` entity by using an explicit entity alias in Application and
  Infrastructure.
- Added the authenticated triage workflow to the static web interface. Staff can
  select a patient, review triage history, register a risk level and chief complaint,
  and clear the selected context on logout.
- Added the hospitalization vertical slice for FR-03: active admissions with bed
  allocation, patient admission history, and discharge with mandatory notes. Added
  `database/005_hospitalization_schema.sql`, SQL persistence, authenticated API
  endpoints, and Domain/Application tests.
- Completed the web surface for FR-03. Staff can select a patient, admit them to a
  bed, review admission history, and submit discharge notes through the existing
  authenticated API.
